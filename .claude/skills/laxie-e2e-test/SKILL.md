# Laxie E2E Testing Workflow

## Quick Reference

```
Seed Data → Trigger Risk Detection → Verify Resolutions → Test Push → Test UI
```

## Test Flow

### Step 1: Seed Test Data

Use the `seedTestData` Cloud Function:

```bash
# Via Firebase console or curl
curl -X POST https://us-central1-laxie-family-os-f7077.cloudfunctions.net/seedTestData \
  -H "Content-Type: application/json" \
  -d '{"familyId": "test-family-001"}'
```

Or call directly in Firestore:
- Create user in `users/test-user-001`
- Create family rules in `familyRules/test-family-001`
- Ensure `fcmToken` or `expoPushToken` is set for push testing

### Step 2: Trigger Risk Detection

```bash
# Trigger the scheduled risk detector manually
curl -X POST https://us-central1-laxie-family-os-f7077.cloudfunctions.net/triggerRiskDetection \
  -H "Content-Type: application/json" \
  -d '{"familyId": "test-family-001"}'
```

Check Firestore for new documents in:
- `risks/` - New risk should be created
- `resolutions/` - Resolution with status 'scheduled' should exist

### Step 3: Verify Resolution Creation

Check resolution has:
- `status: 'scheduled'`
- `vetoDeadline` set (default 5 minutes from creation)
- `message` generated by GPT Language Actuator
- `autonomyLevel` set (L2/L3/L4)

### Step 4: Test Push Notification

Option A: Wait for execution
- Resolution auto-executes after `vetoDeadline`

Option B: Force execute for testing
```bash
curl -X POST https://us-central1-laxie-family-os-f7077.cloudfunctions.net/forceExecuteResolution \
  -H "Content-Type: application/json" \
  -d '{"resolutionId": "<resolution-id>"}'
```

Verify:
- Push notification received on device
- Resolution status changed to 'executed'
- ActionLog created in `actionLogs/`

### Step 5: Test UI Interactions

#### Test STOP Button (Veto)
1. Open PendingScreen in app
2. Find the scheduled resolution
3. Tap STOP button
4. Verify resolution status → 'vetoed'

#### Test Rollback (within 30 min window)
1. Open AuditScreen in app
2. Find executed action (green badge)
3. Tap "撤回並道歉" button
4. Verify:
   - Apology message generated
   - Resolution status → 'rolled_back'
   - Trust metrics updated

## Important Notes

- **Rollback window**: 30 minutes from execution
- **Expo Push Tokens**: Start with `ExponentPushToken[...]`
- **FCM Tokens**: Longer alphanumeric strings
- **Test Family ID**: `test-family-001`
- **Test User IDs**: `test-user-001`, `test-user-002`

## Common Issues

| Issue | Solution |
|-------|----------|
| No push received | Check token format (Expo vs FCM) |
| Resolution not created | Check risk detection logs |
| GPT message empty | Check OPENAI_API_KEY secret |
| Rollback fails | Check 30-min window hasn't passed |
